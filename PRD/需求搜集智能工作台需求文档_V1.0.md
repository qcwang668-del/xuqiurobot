# 需求搜集智能工作台需求文档_V1.0

## 一、概要说明

### 1、需求背景/目标

由于产品经理日常需求来源高度分散（业务群聊天、客户私聊、会议口头反馈等），需求散落在企业微信聊天记录中，导致需求易遗漏、来源难追溯、口径不统一、重复提出无法感知，从而需要建设一套与企业微信关联的需求搜集管理工具。

本期主要围绕实现"企业微信聊天需求一键上报 → AI 分析提炼 → 待确认人机协同 → 统一需求池管理"的完整链路，进一步实现需求的结构化沉淀与周期汇总。用户层面实现产品经理低打扰收集需求、AI 自动提炼成卡片、人工一键确认入池；系统层面打造独立的需求搜集智能工作台，作为产品团队内部统一的需求池。

本期边界约定（已与需求方确认）：

- 数据获取方式：采用企业微信**智能机器人会话窗口主动上报**方式，不接入会话内容存档；
- AI 模型：接入**公有云大模型 API（火山引擎方舟 ark-code-latest，Auto 模式）**，上报内容出域需做脱敏处理；
- 使用范围：**仅产品团队内部成员**提报与使用；
- 系统归属：工作台为**独立系统**，本期不对接 OA/项目管理工具；
- AI 介入深度：AI 仅负责**提炼 + 生成待确认卡片**，入池需人工确认，不做自动入池与自动优先级判定。

### 1.1 涉及模块描述 / 功能清单

本版本主要围绕实现需求从收集到入池的管理闭环，第一期版本功能包含以下模块：

| 序号 | 模块 | 说明 |
| --- | --- | --- |
| 1 | 企微机器人会话上报（上报入口） | 通过企业微信智能机器人会话窗口提交文字需求，AI 整理后在会话中推送确认卡片完成闭环 |
| 2 | AI 分析提炼服务 | 调用公有云大模型，对上报内容进行意图识别、要素抽取、提炼成需求卡片草稿 |
| 3 | 待确认收件箱 | 网页端兜底管理未在会话中处理的卡片，与会话确认状态实时同步 |

### 1.2 业务流程图

```text
产品成员在企业微信聊天中发现需求
        ↓
在「智能机器人会话窗口」发送需求（文字消息）
        ↓
内容脱敏处理（手机号/身份证/银行卡等敏感信息打码）
        ↓
调用公有云大模型：意图识别 + 要素抽取 + 需求描述提炼
        ↓
        ├─ 非需求信号（纯咨询/闲聊）→ 会话回复提示，不生成卡片
        ↓
机器人在会话中推送【需求确认卡片】（提炼字段 + 确认/修改/忽略按钮）
        ↓
        ├─ 点击"确认入池" → 进入需求池（状态：已确认），会话回执需求编号
        ├─ 回复文字修改意见 → AI 按意见重新提炼，再次推送确认卡片（最多 3 轮）
        ├─ 点击"忽略" → 卡片归档（状态：已忽略，可在网页端恢复）
        └─ 超时未处理 → 卡片归入网页端【待确认收件箱】，会话催办提醒
        ↓
需求池内状态流转：已确认 → 评估中 → 已排期 → 已上线 / 已拒绝
        ↓
按日/周生成汇总摘要，群机器人推送至产品团队群
```

## 二、模块功能描述

### 1、企微机器人会话上报（上报入口）

**功能描述**

用于产品成员在企业微信「智能机器人会话窗口」中直接提交需求。成员像日常聊天一样把需求发给机器人（文字、语音或聊天截图转发），机器人受理后自动整理提炼，并在同一会话窗口中将整理好的需求卡片发回给成员确认，实现"提交 → 整理 → 确认"全流程在会话内闭环，成员无需打开其他系统。

**前置条件**

- 已在企业微信管理后台创建"智能机器人"并开启 API 模式，获取 Bot ID 与 Secret（已确认：机器人「需求助手」，API 模式）；
- 对接方式为官方 SDK 长连接：服务端使用 Bot ID + Secret 启动 SDK 保持长连接收发消息，无需配置公网回调 URL，服务可部署在内网主动出站连接；
- 注意区分机器人类型：群机器人（仅 Webhook）只能推送消息、无法接收用户消息，不满足本会话交互场景，必须使用支持消息回调的智能机器人；
- 机器人需对全体产品团队成员可见，成员通过搜索或工作台进入会话窗口。

**数据来源**

- 用户通过智能机器人会话消息回调提交的文本消息；
- 本期仅支持文本消息，语音、图片等非文本消息不进入提炼流程，收到后回复提示引导改为文字提交。

**开发页面 / 能力清单**

- 智能机器人 API 模式接入：官方 SDK 长连接（Bot ID + Secret 鉴权），SDK 内置鉴权与加密传输；
- 消息接收与类型分发（文本/语音/图片）；
- 机器人消息回复能力（文本/Markdown/模板卡片消息）；
- 需求确认模板卡片及按钮交互回调（确认入池/修改/忽略）。

**逻辑说明**

- 成员向机器人发送消息后，会话即时回复受理回执："已收到，正在整理分析，稍后将整理结果发您确认。"
- 本期仅支持文本消息，文本直接进入脱敏与 AI 提炼流程；收到语音、图片等非文本消息时，会话回复提示"本期暂支持文字提报，请将需求以文字形式发送"；
- 支持成员一次发送多条消息描述同一需求，系统将 5 分钟内同一成员的连续消息合并为一次上报处理；
- 提炼完成后，机器人在会话中推送【需求确认卡片】，卡片展示：标题、需求类型、紧急度、来源对象、期望时间、需求描述摘要、AI 置信度，下方按钮：确认入池 / 修改 / 忽略；
- 确认入池：成员点击"确认入池"，卡片写入需求池，机器人回复回执"已加入需求池，需求编号：XQ-YYYYMMDD-XXX"；
- 修改：成员直接回复文字修改意见（如"标题改成 XXX，紧急度改为高"），AI 结合修改意见重新提炼并再次推送确认卡片，同一条需求最多修改 3 轮，超过则提示前往网页端编辑入池；
- 忽略：成员点击"忽略"，机器人回复"已忽略，如需恢复可在网页端待确认收件箱操作"；
- 会话中的确认/忽略操作与网页端待确认收件箱状态实时同步，任一端处理后另一端同步更新；
- 成员发送"帮助"或"?"，回复使用说明（支持的上报方式、确认操作说明、示例格式）；
- 超时未处理：48 小时未在会话中确认的卡片，机器人会话内催办一次；超过 7 天仍未处理的，归入网页端待确认收件箱，按收件箱催办规则执行。

**异常/提示说明**

| 场景 | 提示文案 |
| --- | --- |
| 收到语音/图片等非文本消息 | 本期暂支持文字提报，请将需求以文字形式发送 |
| 大模型调用超时/失败 | 需求分析暂时失败，系统已记录原始内容，稍后自动重试，结果将另行通知 |
| 非需求类消息 | 未识别到明确的需求信息，如需提报需求，请描述具体场景与期望效果 |
| 修改轮次超过 3 轮 | 本条需求已修改 3 轮仍未确认，请前往工作台网页端编辑后入池 |

### 2、AI 分析提炼服务

**功能描述**

用于对上报内容进行智能分析，识别是否构成需求信号，并提炼为结构化需求卡片草稿。该模块是系统核心价值层，围绕实现"原文 → 结构化卡片"的自动转化，提炼结果一律进入待确认状态，不直接入池。

**数据来源**

- 模块 1 上报并经脱敏处理后的文本内容；
- 火山引擎方舟 ark-code-latest 大模型 API 返回的结构化分析结果（Auto 模式，按"效果 + 速度"双维度自动选择模型）。

**处理流程**

1. **内容脱敏**：调用大模型前，对文本中的手机号、身份证号、银行卡号等敏感信息正则打码（替换为 `***`）；企业名称、人名默认保留以维持语义，可在系统管理中配置扩展脱敏词表；
2. **意图识别**：判定消息类型，枚举值：新需求 / 体验优化 / 缺陷反馈 / 纯咨询闲聊。判定为"纯咨询闲聊"时不生成卡片，仅向提出人回复提示；
3. **要素抽取**：提炼标题、需求描述、业务场景、来源对象（客户/内部部门/个人）、期望时间、紧急度表述；
4. **置信度评估**：输出 0~1 的提炼置信度，低于 0.6 时在卡片上标记"提炼质量较低，请重点核对"；
5. **生成需求确认卡片**：通过机器人会话向提出人推送【需求确认卡片】（会话确认为主），同步写入待确认收件箱（网页端兜底），任一端确认后状态实时同步。

**输出字段规则**

| 字段 | 说明 |
| --- | --- |
| 标题 | 必填。AI 生成，不超过 30 字，概括需求核心诉求 |
| 需求描述 | 必填。AI 基于原文提炼，包含业务场景与期望效果，不超过 500 字 |
| 需求类型 | 必填。枚举值：新需求/体验优化/缺陷反馈 |
| 来源对象 | AI 抽取。客户名称/部门名称/个人姓名，无法识别时为空 |
| 期望时间 | AI 抽取原文中的时间表述（如"月底前"），无法识别时为空 |
| 紧急度 | AI 依据原文语气判定。枚举值：高/中/低，默认中 |
| AI 置信度 | 系统生成。0~1 两位小数 |
| 原文引用 | 系统生成。脱敏后的原始上报内容全文，不可编辑 |

**异常/提示说明**

- 大模型返回结果字段缺失或格式异常时，系统自动重试 1 次；重试仍失败则生成"仅含原文"的待确认卡片，标题标记"【待人工提炼】"，并记录错误日志；
- 单次提炼调用超过 30 秒未返回，按调用失败处理，进入自动重试队列，最多重试 3 次。

### 3、待确认收件箱

**功能描述**

用于在网页端兜底管理 AI 提炼生成的待确认需求卡片。需求确认以机器人会话内操作为主，本模块作为会话确认的补充与兜底：未在会话中处理的卡片、修改超过 3 轮的卡片、已忽略卡片的恢复，均在本模块处理。用户进入页面后，默认展示全部待确认卡片，提出人可对本人上报的卡片进行确认入池、编辑后入池、忽略操作；产品负责人可处理全部成员的待确认卡片。会话端与本模块的处理状态实时同步。

**数据来源**

AI 分析提炼服务生成的待确认需求卡片数据。

**开发页面**

- 待确认卡片列表页；
- 卡片详情页（含原文对照）；
- 卡片编辑页（确认前修正）。

| 原文引用 | 只读展示，不可编辑 |
| 提出人 | 只读展示，系统取上报人企业微信账号 |

**其他特殊业务逻辑**

- 待确认卡片超过 7 天未处理，系统通过机器人会话向提出人发送催办提醒，每 3 天提醒一次，最多提醒 3 次；
- 同一提出人的待确认卡片超过 20 张时，列表顶部展示提示"您有较多待确认卡片，建议及时清理"。

### 4、需求池管理

**功能描述**

用于管理已确认入池的全部需求卡片，是产品团队的统一需求池。通过该模块实现需求的查看、编辑、状态流转与频次追踪，支撑后续版本规划与评审。

**数据来源**

待确认收件箱中"确认入池"及"编辑后入池"的需求卡片。

**开发页面**

- 需求池列表页；
- 需求详情页（含原文证据链、状态流转记录）；
- 需求编辑页。

- 状态流转操作仅产品负责人可执行；
- 流转为"已拒绝"时必须填写拒绝原因（文本输入，必填，最大 200 字）；
- 状态流转全程记录操作人、操作时间、原状态、新状态，详情页可查看流转记录。

**列表排序规则**

默认按照更新时间进行降序排序，该模块支持创建时间、更新时间、提出次数手动点击排序。

**列表按钮逻辑说明**

- 新增：点击当前页打开新增页面，支持手工补录需求（字段同编辑页），提交时需要进行标题必填、模块必填、标题排重（与池内需求标题完全一致时提示"已存在相同标题需求：XXX，是否仍要保存？"，二次确认后可保存）校验；
- 详情：点击详情按钮，当前页面跳转至对应详情页面，展示卡片字段、原文引用、状态流转记录；
- 编辑：点击编辑，当前页面跳转至编辑页面，点击提交需要校验必填项，编辑后原 AI 提炼值保留在变更记录中；
- 状态流转：列表行内下拉操作，按状态流转规则执行，流转为已拒绝需弹窗填写拒绝原因；
- 删除：点击删除需要二次确认，弹窗文案"删除后不可恢复，确认删除该需求？"，仅产品负责人可操作；
- 导出：点击导出，按照当前筛选条件导出 Excel 数据。

**列表筛选条件字段说明**

| 字段 | 说明 |
| --- | --- |
| 标题/描述 | 文本输入框检索，针对标题、需求描述字段进行关键词模糊匹配 |
| 所属模块 | 下拉选择，枚举值来源于模块配置 |
| 需求类型 | 下拉选择，枚举值：新需求/体验优化/缺陷反馈 |
| 状态 | 下拉选择，枚举值：已确认/评估中/已排期/已上线/已拒绝 |
| 紧急度 | 下拉选择，枚举值：高/中/低 |
| 来源对象 | 文本输入框检索，针对来源对象字段进行关键词模糊匹配 |
| 提出人 | 下拉选择，枚举值为产品团队成员名单 |
| 入池时间 | 日期范围选择，按照入池时间进行筛选 |

**列表表头字段取值规则（仅对特殊字段做说明）**

| 字段 | 取值规则 |
| --- | --- |
| 提出次数 | 系统统计。需求入池后，后续上报内容经 AI 判定与该需求语义高度相似时，不新建卡片，该字段 +1 并记录新的原文引用；默认值为 1 |
| 来源对象 | 多值展示，同一需求被不同来源重复提出时追加记录 |
| 期望时间 | 展示 AI 抽取的原文时间表述，人工可在编辑页修正为标准日期 |

**其他特殊业务逻辑（相似需求归并）**

- 新卡片确认入池时，系统基于语义相似度与池内"未关闭"需求比对；
- 相似度超过阈值（默认 0.85，可在系统管理中调整）时，弹窗提示"检测到相似需求：XXX（相似度 0.XX）"，用户可选"合并至已有需求"（已有需求提出次数 +1、追加原文引用）或"仍新建"；
- 合并操作记录操作人与时间，已合并卡片不单独展示，其原文引用并入目标需求的证据链。

### 5、汇总播报

**功能描述**

用于按周期生成需求汇总摘要，并通过企业微信群机器人推送至产品团队群，让团队感知需求收集动态，无需登录工作台即可了解概况。

**数据来源**

需求池及待确认收件箱的需求卡片数据，AI 聚类摘要结果。

**逻辑说明**

- 支持每日播报与每周播报两种频率，播报时间在系统管理中配置（每日默认 18:00，每周默认周五 18:00）；
- 每日播报内容：当日新增上报数、确认入池数、待确认存量数、当日入池需求清单（标题+模块+紧急度）；
- 每周播报内容：本周入池需求按所属模块聚类汇总、提出次数 Top5 需求榜、本周状态流转统计（评估中/已排期/已上线数量）；
- 播报消息通过企业微信群机器人 Webhook 推送，支持配置多个目标群；
- 推送失败时系统记录失败日志，并在系统管理中展示最近一次推送状态，连续 3 次失败通过机器人会话向系统管理员发送告警。

**异常/提示说明**

| 场景 | 处理方式 |
| --- | --- |
| 当日/当周无新增数据 | 正常推送，内容为"本周期无新增需求" |
| Webhook 失效 | 推送失败告警，管理员需更新 Webhook 地址 |

### 6、系统管理

**功能描述**

用于维护系统基础配置，仅系统管理员可见。通过该模块实现成员权限、AI 模型、播报、模块字典、脱敏规则的集中配置。

**开发页面**

- 成员管理页：从企业微信通讯录同步产品团队成员，配置角色（成员/产品负责人/系统管理员）；
- 模型配置页：配置大模型 API 密钥、模型名称、Base URL、调用超时时间、相似度阈值；本期接入火山引擎方舟 ark-code-latest 模型，Base URL 使用 OpenAI 兼容协议地址 https://ark.cn-beijing.volces.com/api/coding/v3 （已支持 Responses API），备选 Anthropic 兼容协议地址 https://ark.cn-beijing.volces.com/api/coding ；API Key 加密存储、页面不回显明文，仅支持重置更新；
- 机器人配置页：维护机器人 Bot ID 与 Secret，展示 SDK 长连接状态（已连接/断开），断连时自动重连，连续重连失败通过其他渠道向系统管理员告警；
- 播报配置页：配置播报频率、时间、目标群 Webhook；
- 模块配置页：维护"所属模块"字典（新增、编辑、停用），停用模块不可再被选择，历史数据保留展示；
- 脱敏配置页：维护扩展脱敏词表（如公司内部敏感项目名称）。

**权限规则**

| 功能 | 成员 | 产品负责人 | 系统管理员 |

| 上报需求、处理本人待确认卡片 | 支持 | 支持 | 支持 |
| 处理全部待确认卡片 | — | 支持 | 支持 |
| 需求池查看、编辑、导出 | 支持 | 支持 | 支持 |
| 需求池删除、状态流转 | — | 支持 | 支持 |
| 系统管理配置 | — | — | 支持 |

## 三、非功能性需求

1、数据安全

- 上报内容传输全程加密；机器人消息通过官方 SDK 长连接收发，SDK 内置鉴权与加密传输；
- Bot ID 与 Secret 属于敏感凭证，存储于服务端配置/环境变量中，禁止写入代码仓库、前端页面及对外文档，泄露后需立即在企业微信管理后台重置；
- 调用公有云大模型前必须完成脱敏处理，脱敏词表可配置；
- 原始上报内容、提炼结果存储于工作台独立数据库，本期不与第三方系统共享；
- 系统登录对接企业微信扫码/通讯录授权，非产品团队成员不可访问工作台。

2、性能要求

- 单条上报从发送到生成待确认卡片，正常情况不超过 30 秒；
- 需求池列表查询响应时间不超过 2 秒（万级数据量内）；
- 大模型调用失败自动重试，不因单次失败丢失上报内容。

3、可维护性

- AI 调用日志（请求、响应、耗时、重试记录）保留 90 天，支持按时间查询；
- 相似度阈值、置信度分档、催办规则等参数支持配置化调整，无需发版。

## 四、验收口径

1. 成员在机器人会话窗口发送文字消息，30 秒内在会话中收到【需求确认卡片】；
2. 非需求类消息不生成卡片，提出人在会话中收到对应提示文案；
3. 会话中点击"确认入池"后需求进入需求池，状态为"已确认"，会话收到含需求编号的回执，原文引用完整可查；
4. 会话中回复修改意见后，AI 重新提炼并再次推送确认卡片；会话端与网页端处理状态实时同步；
5. 相似需求入池时弹出合并提示，选择合并后目标需求提出次数 +1；
6. 敏感信息（手机号等）在存储与展示环节均为打码状态；
7. 每日/每周按配置时间向目标群推送汇总播报，无数据时推送空态文案；
8. 无权限角色不可见删除、状态流转、系统管理入口；
9. 需求状态流转、合并、人工修正均留有操作记录，详情页可追溯。
